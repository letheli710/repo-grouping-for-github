# GitHub Group：产品设计（草案 v0.1）

> 2026-11-12。相关调研见 [market-research.md](market-research.md)

## 定位

一个浏览器扩展：在 GitHub 首页左侧边栏里，把「Top repositories」整理成一个个分组。

- **不用登录、不要 token、不连任何服务器。**
- 两个核心目标：
  1. **侧边栏分类**：好看、好找、好整理
  2. **安全**：权限最少、数据不出浏览器、代码公开可查，让人敢装

## 一、侧边栏分类

### 视觉：默认「卡片」，可选「标题色带」「长两翼」

> 2026-11-12 更新：做了 5 个原型（轻量方括号、长两翼、卡片、标题色带、标签页），在真实首页上对比后的结论：
> - GitHub 侧边栏比 Obsidian 更窄、更密，Folder Tools 的淡方括号太弱，看不出分组边界
> - **默认用「卡片」**：每组一张浅灰底、带边框的圆角卡片
> - **「标题色带」和「长两翼」作为可选样式**，在扩展的设置面板（工具栏图标）里切换
> - 轻量方括号和标签页不再保留
>
> 下面是最初的方括号方案，留作记录。

参考 Notebook Navigator Folder Tools 里「子文件夹笔记分组」的样式：

- 每个分组左侧画一个淡淡的「[」方括号，分组名写在方括号上沿
- 组内的条目缩进排在方括号里
- 不画完整的框，比整框更轻，侧边栏本来就窄
- 方括号默认用正文色的 18% 透明度；用户给分组设了颜色时才变色，和 Folder Tools 的规则一致
- 浅色/深色主题都要跟随 GitHub 的颜色变量（`--fgColor-*` / `--borderColor-*`）

示意：

```
Top repositories          🔍 ⚙
┌ 工作 · Acme  3
│  acme-corp/billing-service
│  acme-corp/admin-portal
│  api-server
└
┌ 业余项目  2
│  blog
│  portfolio
└
┌ 基础设施  3
│  infra-terraform
│  k8s-manifests
│  dotfiles
└
  未分组  2
  web-app
  ml-experiments
```

- 同一个 owner 的仓库只显示仓库名，鼠标悬停显示完整的 `owner/repo`
- 别人的仓库保留 `owner/` 前缀，但用淡色显示
- 「未分组」不画方括号，放在最下面，相当于收件箱，新仓库自动进这里

### 交互

| 操作 | 方式 |
|---|---|
| 新建分组 | 标题栏「+」，或者把仓库拖到列表最底部的「新建分组」放置区 |
| 归类 | **拖拽**仓库到某个方括号里；或者悬停仓库时点「⋯」→「移到分组」 |
| 排序 | 组内可以拖动排序；分组之间拖分组名排序 |
| 折叠 | 点分组名折叠或展开，状态记住 |
| 重命名/颜色/删除 | 分组名右键，或者点「⋯」。删除分组后，里面的仓库回到「未分组」 |
| 切回原样 | 设置里一个开关，立即恢复 GitHub 原生列表 |

规则：

- 一个仓库只属于一个分组（文件夹模式），分组只有一层
- 仓库来源 = Top repositories 列表（扩展在页面内自动展开「Show more」，拿到全部条目）
- 已经归了组、但暂时不在 Top repositories 里的仓库，照样显示，因为那是用户自己放进去的
- 第二阶段：在仓库详情页加一个「加入分组」按钮，用来补充很久没动、不在列表里的仓库

### 挂载方式（实测结论）

- 找到 `nav[data-testid="dashboard-repositories"]`，在它前面插入我们自己的根节点，并隐藏原生列表
- 用 Shadow DOM 隔离样式，不去改 GitHub 的 React 组件内部
- 用 `MutationObserver` 应对软导航和重渲染，挂载点没了就自动重新挂上
- **失败要安全**：找不到挂载点，或者渲染出错时，**绝不隐藏原生列表**。最坏的结果是「和没装一样」，不能是「侧边栏空了」

## 二、安全设计

用户装 GitHub 相关扩展，最怕的是：偷看私有代码、偷 token 或 cookie、把仓库名传到外面，以及以后被卖给别人后偷偷作恶。下面逐条回应。

> 2026-11-12 更新（0.3.0，根据 [安全与边缘场景检查](security-and-edge-case-audit.md)）：
> - **对外说法改准确**：不说「只申请 storage」和「零网络请求」。改为「API 权限只有 storage，另有 github.com 网站访问权限；不向开发者或任何第三方服务器发送数据；间接请求只指向 GitHub 自己（复用原生头像地址、点击 Show more）」
> - **分组按 GitHub 账号隔离**，读不到登录账号时不工作；旧的全局数据只在确认归属后迁移
> - **保存改为「在最新版本上重放操作」**，多标签页不互相覆盖；保存失败可见、可重试或撤销；读取失败不接管侧边栏
> - **头像保留**（产品取舍）：只复用 GitHub 原生列表里同一个 `avatars.githubusercontent.com` 地址，不引入新的域名
> - `connect-src 'none'` 只约束扩展页面，**不能作为内容脚本不联网的证明**；这一点靠代码和自动检查保证
>
> 下面各节保留最初的设想；其中与上面冲突的地方，以上面为准。

### 1. 权限最少

```jsonc
// manifest.json（MV3）
"permissions": ["storage"],
"content_scripts": [{ "matches": ["https://github.com/*"], ... }]
```

- **只申请 `storage` 一个权限。** 没有 `tabs`、`cookies`、`webRequest`、`identity`、`scripting`、`<all_urls>`，也没有后台常驻逻辑
- 只在 `github.com` 上运行，安装时 Chrome 只会显示「读取和更改您在 github.com 上的数据」这一条
- 为什么是 `github.com/*` 而不是只匹配首页：GitHub 用软导航，从仓库页点回首页时页面不会重新加载，只匹配首页的话扩展会注入不上。代码里会先判断当前路径，不是首页就什么都不做
- 第一版不碰 `api.github.com`

### 2. 数据不出浏览器

- **不上传数据**：不 `fetch`，不 `XMLHttpRequest`，没有统计、没有错误上报、不加载远程代码（MV3 本身也禁止远程代码）。间接请求只指向 GitHub 自己（见上方 0.3.0 更新）
- 扩展自己的页面设 `connect-src 'none'` 的 CSP
- CI 里加一道检查：源码和打包产物中出现 `fetch(`、`XMLHttpRequest`、`WebSocket`、`sendBeacon` 就构建失败
- 只存这些：分组名、颜色、顺序、仓库全名 `owner/repo`、折叠状态。**不存代码、不存 token、不读 cookie**
- 在页面里只读侧边栏那几个链接的 `href` 和文字，其他内容一概不碰

### 3. 同步默认关闭，用户选择开启

- 默认存在 `chrome.storage.local`，只留在这台电脑上
- 设置里可以打开「通过 Chrome 账号同步」，改用 `chrome.storage.sync`，数据走用户自己的 Google 账号同步
- 打开前明确提示：「私有仓库的名字会随你的 Chrome 同步到其他设备」
- 理由：私有仓库名本身就可能是敏感信息，比如客户名、未公开的项目，由用户自己决定要不要同步

### 4. 只读，绝不替用户操作 GitHub

- 不点任何按钮（自动展开「Show more」除外，这个只是读取）、不提交任何表单、不 star 或 watch、不修改仓库
- 分组只是「视觉上的整理」，不改变仓库本身和访问权限

### 5. 防止注入（XSS）

- 仓库名和分组名一律用 `textContent` 渲染，**不用 `innerHTML`**
- 导入 JSON 时严格校验：字段白名单、仓库名必须匹配 `^[\w.-]+/[\w.-]+$`、分组名长度上限、文件大小上限（比如 1MB），不合法就整份拒绝

### 6. 透明、可验证

- 开源（MIT），打包产物**不压缩**，审核人员和用户都能直接读懂
- **运行时零依赖**，只有构建工具，减少供应链风险
- 发布时用 GitHub Actions 构建，附上 artifact attestation，可以证明商店里的包就是这份源码构建出来的
- README 第一屏放「这个扩展能看到什么 / 不能看到什么」表格
- 隐私政策只有一句：「我们不收集任何数据。」

### 7. 对未来的承诺（防止被卖后作恶）

- 写进 README：**永远不增加网络权限和数据上传**。如果将来确实需要新权限，必须先发公告，并单独发一个大版本
- 好在 Chrome 本身就有保护：扩展更新后要求的权限变多时，Chrome 会自动停用它，等用户重新确认

## 三、范围

**v1（MVP）**

- 首页 `/dashboard`、`/feed` 侧边栏分组：方括号样式、拖拽归类、「⋯」菜单、折叠、颜色、重命名、删除
- 「未分组」区，以及一键切回原样
- 本地存储；同步默认关闭，可选开启
- 导入/导出 JSON
- 上面列出的全部安全措施

**v2**

- 仓库页「加入分组」按钮
- 左上角汉堡菜单抽屉里也显示分组
- 自动建议分组（按 owner 或名称前缀）
- Firefox 版

**不做**

- 登录或账号系统
- 服务器
- token 或 GitHub API（除非以后做成用户主动开启的可选项，并单独说明）
- 嵌套分组
- 团队共享
